# AI-led research decision engine v1

## Architecture

`app/v2/ai_led_research.py` adds a versioned two-phase workflow on the existing provider-neutral `.complete()` interface, `StrategyRegistry`, `SafetyGate`, and append-only `V2AuditLedger`.

1. **Discovery:** `AIHypothesisDiscoveryService` receives only the timestamped feature context and data hashes. It can return at most three falsifiable hypotheses, each with a mechanism, entry/exit/invalidation conditions, required features, horizon, evidence, uncertainty, and falsification criteria. Discovery output is recorded separately. It is not executable strategy code and is never evaluated in the same call.
2. **Registration:** `StrategyHypothesis.from_mapping` canonicalizes the proposal and derives an ID from its content hash. Only a proposal matching a prior successful discovery ledger event can be registered. Registration writes a second immutable ledger event and adds the candidate to the in-memory registry as `RESEARCH_ONLY`, paper-disabled. A revision gets a new hash/ID. New candidates cannot be registered after the ledger contains decision records; freeze the discovery and candidate set first. Existing hypotheses are loaded from the append-only event stream with identity and status checks.
3. **Decision:** `AIResearchDecisionService` sends the eligible symbols, every supplied feature with its timestamp, market context, input file hashes, and registered strategy descriptions/versions to the injected provider. The AI may independently rank symbols, assess regime, select a registered strategy, and choose BUY/HOLD/EXIT/NO_TRADE. It does not need a frozen V1 signal. Strict parsing rejects missing/extra fields, incomplete rankings, unregistered IDs, contradictory trade fields, invalid prices, horizons, or cost estimates.
4. **Risk and audit:** `AIResearchController` maps actionable recommendations into the existing Python `SafetyGate`. The gate must share the exact registry used by the AI service. Rejected BUY/EXIT decisions end as HOLD; NO_TRADE or provider/data failures remain NO_TRADE. Decisions, risk outcomes, model/provider identifiers, versions, timestamps, prompt/input hashes, strategy catalog details, latency/tokens when supplied, features, and input hashes are persisted in the append-only SQLite ledger. This research controller intentionally has no paper executor reference and cannot create a paper fill.

The discovery prompt and decision prompt are separately versioned. Neither provider output nor model confidence is considered validated strategy logic or a calibrated probability. An alternative provider/model is accepted only when the caller explicitly enables substitution; otherwise substitution fails closed and its identifiers are retained in the audit envelope.

## Reproducibility and safe use

Use an injected provider implementation and an `AIResearchRequest` built from an already authorized, timestamp-valid feature snapshot. Input hashes are mandatory. Current provider adapters are not invoked by tests or construction. Do not load credentials from `.env`; if a later separately authorized run configures a provider, credentials stay outside requests and audit payloads.

The request records source-provenance status and explicit data-quality issues. Stale, future, incomplete, invalidly hashed, explicitly quality-flagged, or look-ahead/outcome-named inputs return NO_TRADE without calling the provider. Input hashes identify supplied bytes but do not authenticate them; feature names alone cannot prove a supplied rolling indicator was computed causally. The present cached market dataset still has unresolved request lineage, timestamp semantics, adjustment status, and survivorship; all related recommendations would remain exploratory and unsuitable for a validation claim.

## Execution boundary

AI hypotheses are always registered as `RESEARCH_ONLY` and paper-disabled. The existing `SafetyGate` independently checks current-day data, authoritative session validation, kill switch, duplicate decisions, registry status, price/stop/target/horizon bounds, sizing, capital, daily loss, trade count, and open positions. Research-only candidates are rejected for execution by that gate. Even a separately paper-approved candidate is only risk-checked and audited by this new controller; no paper executor is attached. No live broker interface is added, and this task did not call a provider or run an evaluation.

The source universe and chronological holdout are not proven complete or independent. There is no exact point-in-time model history. No matched V1/V2 performance evaluator was run or added here: fabricating historical AI outputs or treating current-model calls on old candles as observed decisions would be invalid, and the existing cached data are not cleared for evaluation. A later approved evaluation needs a documented source acquisition, verified timestamp/session semantics, integrity and corporate-action policy, frozen universe and cost assumptions, a prospective point-in-time AI decision log, and a predeclared chronological evaluation protocol matched to frozen V1. This implementation supports decision research and audit only; it does not establish a backtest, performance, profitability, or paper readiness.
